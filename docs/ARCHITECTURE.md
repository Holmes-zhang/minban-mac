# 工作方式

## 应用

1. 校验 Windows 11 x64；创建并核对本工具数据目录的归属标记。
2. 准备独立便携运行环境。下载版本固定，缓存按 SHA256 检查；安装包另外检查 Authenticode。下载未完成或校验失败时不切换原方案。
3. 检查同名任务冲突、标准安装版服务，记录原便携版进程、当前用户的直接 Windhawk 启动任务及启动文件夹快捷方式。任务签名包括动作及运行身份。
4. 在可见修改之前写入本地事务记录；暂停原启动项及原工具。脚本修改的注册表值先写撤回信息，再修改已有键的单值。
5. 将四个上游模组及附带独立提醒的对应源码复制到独立 Runtime，生成 UTF-16 LE INI；引擎仅允许 explorer.exe，不启用游戏或关键进程注入。
6. 注册当前用户的无额外延迟登录任务，启动便携版 Windhawk。在当前会话 Explorer 中检查当前启用的模块是否加载。
7. 异常时尝试恢复，并显示不能自动处理的事项。

同一用户同一会话的切换操作用命名互斥锁防止同时执行。重复应用不把已经美化的状态重新当作原始备份。

常规下载使用系统默认 TLS 协商，结束后恢复进程原配置；传输失败时尝试 Windows System32 中的 curl，禁止 HTTP 跳转并保留证书校验，不读取个人 curl 配置。有效传输仍须通过 SHA256；错误内容不触发下载重试绕过校验。用户也可按官方地址用浏览器下载，经导入入口校验后放入 Cache。导入入口不执行程序、不停用启动项、不改注册表。

## 恢复

核对本机记录的归属和运行路径 → 移除动作仍匹配的自有登录任务 → 正常退出本包 Windhawk → 恢复脚本改动的单个显示设置 → 恢复动作与身份仍匹配的原任务、哈希仍匹配的原快捷方式 → 启动原先运行的工具。

不是磁盘镜像式还原：其他工具或用户后续修改过的内容保留并提示检查。缓存和备份不删除。突发断电、资源管理器异常或权限变化可能仍需手动处理，错误文字和 state.json 是排查依据。

## 数据边界

项目目录可移动，实际启动路径在用户本地 Runtime 中。恢复记录、缓存、日志和个人代理设置不放进公开项目。公开配置只包含通用参数。

本项目没有在线遥测或自建服务器。所需官方下载、Windhawk 自身的网络行为和 Windows 符号下载可能联网；这不是无网络软件。

依赖清单为普通 JSON：每个模组同时记录对应版本程序和源码的 URL 与 SHA256。构建脚本采用明确允许清单，不从用户的运行目录收集文件。

## Beta附带组件与升级

bundledMods单独描述本项目提醒DLL及五份完整对应源码。下载第三方组件前先验证附带文件；生成运行配置时再次校验，并将源码及头文件复制到Runtime/AppData/ModsSource。公开ZIP按清单收集自制DLL与对应源码，不收集实际运行目录。

开启/关闭提醒入口仅接受有效的本包启用记录和已知组件库名，只改自己的Disabled值。preferences.local.json保存选择；重新应用与加载检查尊重关闭状态。升级和重新应用会先退出自有Windhawk，避免覆盖仍加载的DLL；沿用首次启用记录，不重新备份已美化的状态。

当前隐藏预设检查同屏幕可见最大化窗口，而非仅前台窗口；自动阻止其他工具争用XAML诊断接口。提醒日志默认关闭，仅在本机显式开启后记录应用名称、显示阶段和图标坐标，不读取通知正文或联系人。
