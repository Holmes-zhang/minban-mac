# 工作方式

## 应用

1. 校验 Windows 11 x64；创建并核对本工具数据目录的归属标记。
2. 准备独立便携运行环境。下载版本固定，缓存按 SHA256 检查；安装包另外检查 Authenticode。下载未完成或校验失败时不切换原方案。
3. 检查同名任务冲突、标准安装版服务，记录原便携版进程、当前用户的直接 Windhawk 启动任务及启动文件夹快捷方式。任务签名包括动作及运行身份。
4. 在可见修改之前写入本地事务记录；暂停原启动项及原工具。脚本修改的注册表值先写撤回信息，再修改已有键的单值。
5. 将四个模组及对应源码复制到独立 Runtime，生成 UTF-16 LE INI；引擎仅允许 explorer.exe，不启用游戏或关键进程注入。
6. 注册当前用户的无额外延迟登录任务，启动便携版 Windhawk。在当前会话 Explorer 中检查四个模块是否加载。
7. 异常时尝试恢复，并显示不能自动处理的事项。

同一用户同一会话的切换操作用命名互斥锁防止同时执行。重复应用不把已经美化的状态重新当作原始备份。

## 恢复

核对本机记录的归属和运行路径 → 移除动作仍匹配的自有登录任务 → 正常退出本包 Windhawk → 恢复脚本改动的单个显示设置 → 恢复动作与身份仍匹配的原任务、哈希仍匹配的原快捷方式 → 启动原先运行的工具。

不是磁盘镜像式还原：其他工具或用户后续修改过的内容保留并提示检查。缓存和备份不删除。突发断电、资源管理器异常或权限变化可能仍需手动处理，错误文字和 state.json 是排查依据。

## 数据边界

项目目录可移动，实际启动路径在用户本地 Runtime 中。恢复记录、缓存、日志和个人代理设置不放进公开项目。公开配置只包含通用参数。

本项目没有在线遥测或自建服务器。所需官方下载、Windhawk 自身的网络行为和 Windows 符号下载可能联网；这不是无网络软件。

依赖清单为普通 JSON：每个模组同时记录对应版本程序和源码的 URL 与 SHA256。构建脚本采用明确允许清单，不从用户的运行目录收集文件。
