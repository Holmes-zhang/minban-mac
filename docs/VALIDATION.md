# 验证范围

## 外观基线

用户当前使用的配置已在 Windows 11 build 26200 / Explorer 10.0.26100.9444 上调试，确认圆角、时钟显示完整、原生搜索、左下角空白不触发、应用区域与托盘区域可唤起。用户重启后确认启动速度可接受。

这验证了预设的实际使用效果，不等于新分发包已在所有 Windows 11 版本验证。

## 自动检查

1.0.2 共通过 92 项隔离检查，保留了首版缺失 Execute 的回归场景，并增加证书失败、备用下载和手动导入覆盖。

tests/Validate.ps1 使用临时文件夹、随机独立注册表测试键及模拟的进程和任务：

- Windows PowerShell 5.1 语法与 UTF-8 BOM 编码。
- 依赖清单、官方地址、SHA256 格式与预设结构。
- 下载内容校验、损坏缓存拒绝、正确缓存复用和路径越界拒绝。
- 模拟证书信任失败后备用下载成功；两条路径均失败时给出导入和证书排查指引。
- 备用下载的错误内容拒绝、未完成临时文件清理、HTTPS 限制和代理参数传递。
- 浏览器下载文件按固定哈希识别，未知版本拒绝；安装包签名不受信任时拒绝导入。
- 导入保留原下载文件，不覆盖损坏的已有正式缓存，不执行组件程序。
- Windhawk 配置生成、UTF-16 LE 编码与运行库目标名称。
- 注册表单值恢复、原先缺失值的恢复、保留后续外部修改。
- 应用前持久化撤回记录、重复应用不覆盖原备份。
- 恢复原启动状态和快捷方式；加载失败自动撤回。
- 重复恢复不再次修改。
- COM 动作、空动作、多个动作和缺失程序路径不会被当成 Windhawk 启动项。
- 混合计划任务扫描不会再因缺失 Execute 中断；只记录当前用户的单一 Windhawk 程序启动动作。

测试不会启动 Windhawk、改变真实任务栏、创建真实登录任务或下载第三方文件。随机测试键结束时删除，临时测试文件保留，便于审查。

## 分发核查

依赖版本对应的官方模组源码与现有已使用的模组程序已核对 SHA256。发布 ZIP 采用允许清单，只包含本项目源文件、配置、说明、许可及用户提供的桌面效果截图，没有第三方二进制、缓存、个人路径、独立壁纸文件、聊天截图或恢复记录。

## 1.0.1 的真实任务扫描

使用系统自带 Windows PowerShell 5.1，在本机真实任务列表上复现了 1.0.0 的 Execute 属性错误。使用修复后的扫描逻辑，正常识别 10 个程序任务，跳过 4 个 COM 任务。此检查只读任务，没有注册、停用或启动任务与软件。

任务动作的不同类型可参考 [Microsoft 的 Task Actions 说明](https://learn.microsoft.com/en-us/windows/win32/taskschd/task-actions)。这些结果覆盖本次属性错误，不代表已完成其他电脑上的首次安装和视觉回归。

## 1.0.2 的真实下载核查

在 Windows PowerShell 5.1 中从官方地址实际下载固定版本的模组源码，验证常规下载与系统 curl 下载结果相同且均匹配清单 SHA256。备用路径的入口通过模拟常规下载器抛出证书信任异常触发，curl 的 HTTPS 下载与校验为真实操作。

另在独立测试目录导入真实的官方 Windhawk 1.7.3 安装包，验证 SHA256、Authenticode 签名和缓存文件名。核查没有执行安装包、启用 Windhawk、修改真实任务栏或登录任务。

这些结果验证了下载兼容和手动导入流程，无法证明修复了反馈电脑自身的证书信任问题。系统根证书、时间、代理或组织策略的问题仍需在对应电脑核对。备用下载保持证书验证；导入也不绕过签名信任检查。

## 尚未覆盖

新电脑上的首次联网安装、不同 Windows 补丁、多屏、高 DPI、ARM64、组织策略、其他美化软件冲突以及突发断电没有完整实机回归。新包的一键管理流程通过隔离模拟验证；现有桌面保持原配置，没有用新包覆盖以伪称完整实机验收。

因此本版应先试用并保留恢复入口，首次公开发布建议标记为试用版本。DLL 加载检查只确认模块存在，不保证每个视觉行为都符合预期。
